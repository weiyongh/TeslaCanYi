# L3-Charge-Slow-FullCycle Case契约

**Case ID：** `L3-Charge-Slow-FullCycle`  
**用途：** 正常交流慢充完整生命周期基线  
**形成日期：** 2026-09-10  
**当前状态：** 已审核通过  

## 1. Case目标

从L3交流慢充知识中选择正常完整生命周期作为独立实车验证范围，证明慢充能够从未连接状态，经连接识别、充电建立和短时保持，完成正常停止与断开。

本Case只定义为什么采、最低限度必须证明什么以及需要观察什么，不定义具体现场Event、VoiceRunner播报或Candidate Signal。

## 2. Case范围

```text
未连接
→ 连接被识别
→ 准备/许可推进
→ 实际交流供电建立
→ 车辆侧功率转换形成
→ Pack形成真实充电结果
→ 正常充电短时保持
→ 正常停止
→ 功率与状态退出
→ 解锁/断开
```

本Case不覆盖预约充电、电流阶跃、长时间热稳定、达到SOC上限自动停止、故障注入或异常拔枪。

## 3. Evidence Requirements

| ER | 名称 | 必须证明的核心事实 |
| --- | --- | --- |
| ER-01 | 连接识别成立 | 系统能够从未连接状态进入已识别交流充电连接的状态 |
| ER-02 | 准备/许可推进成立 | 连接被识别后，系统能够推进到允许正常充电建立的准备/许可阶段 |
| ER-03 | 实际交流供电成立 | 正常启动请求后，充电设施与车辆之间能够建立实际交流供电 |
| ER-04 | 功率转换成立 | 交流供电建立后，车辆能够形成实际的交流到直流功率转换 |
| ER-05 | Pack充电结果成立 | 车辆侧功率转换最终使Pack出现真实充电结果 |
| ER-06 | 正常充电保持成立 | 正常充电能够保持一个足以区别于启动瞬态的短时窗口 |
| ER-07 | 正常退出成立 | 正常停止后，充电功能能够退出并完成安全断开，回到非充电状态 |

ER只定义需要证明的功能事实，不预设具体ECU、接触器、内部条件、Signal或算法。

## 4. Observable Requirements

OR从ER和L3功能主线、状态迁移及控制关系产生，优先保留现象之间的联合观察和前后对照。

```text
连接事件 ↔ 连接状态
启动请求 ↔ 实际交流供电
交流输入 ↔ 车辆侧直流输出
车辆侧功率输出 ↔ Pack充电结果
建立过程 ↔ 短时持续状态
停止请求 ↔ 功率退出 ↔ 连接解除
```

需要保留以下状态对照：

```text
未连接、未充电
→ 已连接、未启动
→ 正在充电
→ 已停止、仍连接
→ 已断开、未充电
```

| ER | OR | 需要观察的现象或关系 |
| --- | --- | --- |
| ER-01 | OR-01.1 | 未连接与已连接状态能够前后区分 |
| ER-01 | OR-01.2 | 物理连接事件之后出现并保持连接状态 |
| ER-02 | OR-02.1 | 已连接未充电状态区别于未连接和正在充电 |
| ER-02 | OR-02.2 | 连接保持时能够继续推进到实际充电建立 |
| ER-03 | OR-03.1 | 启动请求前后存在实际交流供电差异 |
| ER-03 | OR-03.2 | 启动请求与实际交流供电响应能够分别定位 |
| ER-04 | OR-04.1 | 交流输入建立后出现对应的车辆侧直流输出 |
| ER-04 | OR-04.2 | 交流输入与直流输出的方向和时间关系合理 |
| ER-05 | OR-05.1 | Pack从非充电状态转为实际充电状态 |
| ER-05 | OR-05.2 | 车辆侧功率输出与Pack充电结果在同一过程内对应 |
| ER-06 | OR-06.1 | 启动瞬态结束后存在连续充电窗口 |
| ER-06 | OR-06.2 | 连接、交流输入、车辆侧功率输出和Pack充电结果在同一窗口持续成立 |
| ER-07 | OR-07.1 | 正常停止请求之后充电功能实际退出 |
| ER-07 | OR-07.2 | 已停止仍连接与已断开连接能够区分 |
| ER-07 | OR-07.3 | 断开后回到可与开始状态比较的非充电状态 |

孤立变量变化不足以构成完整OR。若某个OR暂时无法直接观察，仍保留该观察要求，不降低ER或OR抽象层级迎合现有DBC。

## 5. Case边界

- Case契约不包含Vehicle ID或具体车型名称。
- 现场设施、操作入口、显示能力和记录方式作为共享实现接收的现场条件输入，不属于本Case语义。
- Event、Experiment Plan和VoiceRunner Script由共享实现根据已审核Case契约及现场条件生成。
- Candidate Signal与DBC在Case契约审核并冻结后进入后续可观测性评估与Evidence Mapping，不得反向改写Case、ER或OR。
